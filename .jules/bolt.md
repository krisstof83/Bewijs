## 2024-05-24 - SQLite Bulk Insert Bottleneck & Transaction Leakage
**Learning:** Inserting records one-by-one without a transaction in Node.js `sqlite3` forces a disk fsync for every `db.run()`, which acts as a major performance bottleneck. Furthermore, when batching inserts using `db.serialize()`, uncaught synchronous errors (like from `fs.readFileSync`) within the transaction block prevent subsequent database operations (like `COMMIT`) from being queued, causing transaction leakage and permanently locking the database.
**Action:** Always batch multiple inserts using `BEGIN TRANSACTION` and `COMMIT` within `db.serialize()` along with `db.prepare()` to ensure performance scaling. Wrap synchronous operations within the transaction block in a `try...catch` to ensure that `COMMIT` is executed or transaction is properly handled (although rolling back is harder in node-sqlite3 without proper flow, we just want to ensure we don't leak uncommitted state or crash).
