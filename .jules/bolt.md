## 2024-05-15 - SQLite Batch Insert Bottleneck & Transaction Leakage
**Learning:** In Node.js `sqlite3`, inserting records one-by-one outside a transaction forces a disk fsync for every `db.run()`, acting as a major performance bottleneck for bulk operations. Furthermore, when batching operations inside `db.serialize()`, if synchronous operations like `fs.readFileSync` throw an uncaught error, subsequent commands (like `COMMIT`) may not be queued, causing the transaction to remain open and permanently locking the database for that session.
**Action:** Always batch multiple `INSERT` statements using `BEGIN TRANSACTION`, `db.prepare()`, and `COMMIT` within `db.serialize()`. Ensure that any synchronous code executing inside the transaction block is wrapped in a `try...catch` block to prevent uncaught exceptions from leaking the transaction.
