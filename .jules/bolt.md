## 2024-06-18 - SQLite Batch Inserts with Synchronous Operations
**Learning:** In Node.js `sqlite3`, inserting records one-by-one without a transaction forces a disk fsync for every `db.run()`, which is a major performance bottleneck. However, when batching inserts inside `db.serialize()`, if a synchronous operation (like `fs.readFileSync`) throws an error that isn't caught, the script execution aborts locally. Since `sqlite3` operations are queued asynchronously, an uncaught synchronous error will prevent subsequent database operations (like `COMMIT`) from being enqueued, leaving the transaction open and permanently locking the database for the session.
**Action:** Always batch multiple SQLite inserts using `BEGIN TRANSACTION` and `COMMIT` within `db.serialize()` along with `db.prepare()`. Crucially, ensure that synchronous operations within the transaction block are wrapped in a `try...catch` block so that errors are caught and the transaction can be safely completed or rolled back.
