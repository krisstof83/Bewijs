## 2024-06-13 - SQLite Transactions with Synchronous File Operations
**Learning:** When batching inserts in Node.js `sqlite3` using `db.serialize()` and a transaction (`BEGIN TRANSACTION` / `COMMIT`), if there are synchronous file system calls (like `fs.readFileSync`) mixed in the loop, an uncaught error in the synchronous call will halt the execution of the loop and prevent subsequent database operations (such as the final `COMMIT`) from ever being queued. This leads to an uncommitted, leaked transaction which effectively leaves the SQLite database permanently locked for further writes until the app restarts.
**Action:** Always wrap synchronous operations inside a database batching loop in a `try...catch` block so that failures in one iteration do not break the entire transaction flow and the `COMMIT` is still executed.
