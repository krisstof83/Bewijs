## 2024-06-12 - SQLite Batch Insertion and File Hashing Bottlenecks
**Learning:** In Node.js `sqlite3`, inserting records one-by-one without a transaction forces a disk fsync for every `db.run()`, acting as a major performance bottleneck. Additionally, computing hashes synchronously (using `fs.readFileSync`) blocks the main thread and creates memory bottlenecks for large files. Finally, synchronous operations within a `db.serialize()` transaction block (e.g. `BEGIN TRANSACTION`) must be wrapped in `try...catch` or executed beforehand; uncaught errors will prevent subsequent database operations (like `COMMIT`) from queuing, permanently locking the database due to transaction leakage.
**Action:** Always process large files with asynchronous streams (e.g., `fs.createReadStream`) and accumulate results safely. Then, batch multiple SQLite inserts using `BEGIN TRANSACTION` and `COMMIT` within `db.serialize()` alongside `db.prepare()` to ensure performance scaling and safety from transaction locks.
