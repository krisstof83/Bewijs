## 2024-06-10 - Node.js SQLite Insert Bottleneck & Serialization Risk
**Learning:** In Node.js `sqlite3`, inserting records one-by-one without a transaction forces a disk fsync for every `db.run()`, acting as a major performance bottleneck (e.g. 1921ms without tx vs 116ms with tx). Furthermore, when using `db.serialize()` to batch inserts, uncaught synchronous exceptions (like `fs.readFileSync` failing) will interrupt the sequence, preventing subsequent database operations (like `COMMIT`) from being executed and thus causing transaction leakage / database locking.
**Action:** Always batch multiple inserts using `BEGIN TRANSACTION` and `COMMIT` within `db.serialize()`. When doing so, ensure any synchronous operations inside the block are strictly wrapped in a `try...catch` so that `COMMIT` is still reached.
